# Team-builder client repair

The planner's default challenge activity blocked recommendations whenever live verification failed. Its general ranking rewarded mechanics check counts, allowing covered but awkward compositions to displace complete reviewed teams. Repeated shaping requests accumulated incompatible constraints, and the replacement selector offered teammates for whom no covered replacement existed.

The primary workflow now opens with an account plan. The demo produces Mavuika Melt and Nahida Hyperbloom for Abyss, adding Neuvillette Hypercarry for Stygian. These are unmeasured guide recommendations, not a verified current-cycle or damage ranking. Open generation remains available and is exercised with a personal Nahida/Xingqiu/Kuki/Fischl account outside the recipe set.

Selection favors complete reviewed examples, declared readiness and covered coherent roles. Check counts measure evidence coverage only. Actual build observations still change configuration identity and established build gaps. Unknown roles stay inspectable through complete guide/custom seeds. Original recipe constraints and attribution remain in the expanded details; the visible caution removes clauses about absent optional teammates.

The screen shows roles, readiness, recorded-build coverage, a rationale and a setup caution. Character focus, Another team, Keep this team, whole-plan alternatives and a composition browser are primary controls. Source hashes, detailed checks and ingestion tools remain expandable. Desktop and 390-pixel mobile screenshots were inspected, with no horizontal overflow.

## Challenge preparation

Build against a challenge supports player-entered half/boss targets and explicit matchup preferences. Abyss retains all three stages per half. The real Stygian provider reference includes Secret Source Automaton: Overseer Device, Battle-Hardened Domovoy Sculptor and Guardian Blade of Drifting Snow, with source attribution and an exact fetched-byte hash. Generic begin/end fields select the reference only and are stripped from its public type; it cannot become a verified live pack.

Element/weapon choices express roster preferences. Utility and reviewed mechanical requirements use covered effects. Neither element presence nor a preference establishes shield-breaking speed or a successful clear. Reference prose is available as source data but has no invented executable interpretation.

Targets persist separately per server and mode and round-trip through validated workspace backup/restore. Export distinguishes general exploration, challenge preparation and verified-current planning. Reference and manual targets cannot grant current-cycle verification. The reviewed-publication fallback has a separate timeout controller, so an aborted provider request does not also abort it.

## Feedback

The replacement selector marks teammates with no covered substitute before a request can empty the plan. A newer replacement, variant or playstyle request replaces the earlier shaping requirement for that target. Rejected compositions remain suppressed, and earlier requests remain specifically removable and recoverable with Undo. Exclusions, exact configuration locks, shared Traveler identity and equipped-item ownership remain enforced by joint account allocation.

Legacy stored activity settings migrate to general exploration while retaining the EM-rebuild choice. Existing account preferences, custom teams, inventory and rotation sheets are preserved.

## Remaining gates

Verified-current recommendations need authoritative regional effective dates and complete lineups; the reviewed publication registry remains empty. Abyss provider details currently omit every Floor 12 enemy list. Stygian's period label, countdown and generic provider dates still do not agree on exact validity.

No real reviewed clear pilot is bundled. Individual attributed Stygian.moe references can qualify independently of bulk/training permission, but original-run proof review, encounter mapping and honest actual-build missingness must be completed before publishing those records. Complete artifact/stat equivalence, broader role mechanics and repeat-loop energy/application/timing remain incomplete. No learned ranker or account-specific damage ranking is available.

The next recommendation milestone should compare current account plans and counterfactual plans after each potential pull, with current conditional role/team evidence, actual build readiness, shared-support allocation, encounter coverage and explicit uncertainty. A tier-list ordinal or increase in recipe count alone cannot establish that a pull improves this player's account.
